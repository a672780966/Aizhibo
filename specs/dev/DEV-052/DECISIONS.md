# DEV-052 DECISIONS

本文件记录 DEV-052（Host Persona）实现中的关键决策与理由。Task
Package 第 6 节要求的四个要点逐一覆盖（D1–D4）。

## D1 — 为何不发明具体性格形容词，而是直接复述第 36 节职责列表

**决策**：`voiceDescription` 默认文案只复述 Dev Spec 第 36 节 AI Host
职责列表的八项短语（回复弹幕/主动评论/点名/吐槽行动组/评论骰子/提醒
互动/缓解冷场/建立直播间内部梗），不添加任何性格形容词/语气风格描述
（活泼/毒舌/温柔等）。

**理由**：
- Dev Spec 对 Host Persona 的规范极度稀薄：第 37 节只把它列为 Host
  Context 八项输入之一，第 36 节唯一明确写出的是 Host 的**职责列表**
  （"Host 该做什么"），全篇没有任何地方定义过 Host 的**性格/语气**
  （"Host 是什么样的人"）。
- "活泼/毒舌/温柔"这类性格设定是创作/产品决策，不是工程决策。Dev
  Spec 未定义的内容不能由施工方发明——本仓库既有取舍先例（DEV-050/
  DEV-051："Dev Spec 未定义就不发明"）。
- 职责列表是唯一既权威又确定的文案来源：逐条复述既不越界（内容全部
  有规范依据），又为下游（DEV-055/056 拼 system prompt）提供了真实的
  占位语料。真正的、有创作内容的人设文案留给 USER 未来以某种配置方式
  填入，本节点只搭类型与访问器基础设施（与 DEV-056 "只需一个可替换
  Provider API" 同精神：本节点是基础设施，不是内容创作）。

## D2 — 为何只提供唯一静态默认值，不做可配置的多人设系统

**决策**：`getHostPersona()` 不接受参数，返回模块级唯一的硬编码
`DEFAULT_HOST_PERSONA` 常量；不实现多人设管理/热切换/持久化配置系统。

**理由**：
- Dev Spec 没有任何地方要求"同一场直播支持切换多套人设"或"人设可
  按章节/场景变化"。可配置系统是多出来的工程面（配置源、覆盖层、切换
  时机、校验），在没有规范需求时引入纯属推测性泛化（YAGNI）。
- 人设的"随时间/事件变化"维度在 Dev Spec 里由 **Host Mood（DEV-053）**
  承担，是 Host Context 的另一项独立输入——变化维度不该由 Persona 的
  可配置性重复实现，两者边界清晰。
- 静态常量使行为完全确定、可测试（A09 连续调用一致性直证），也符合
  本节点"静态身份数据"的定位。

## D3 — 为何不接入 Host Scheduler / Host LLM Provider

**决策**：本节点只产出"人设是什么"这一项数据（`HostPersona` 类型 +
`getHostPersona()` 访问器），不 import、不调用、不拼装任何 Host
Scheduler（DEV-055）/ Host LLM Provider（DEV-056）相关代码。

**理由**：
- Dev Spec 第 37 节把 Host Persona 只列为 Host Context **八项输入之一**；
  把八项输入拼装成真正喂给 LLM 的 prompt 是 Host Scheduler + Host LLM
  Provider 的职责，不是本节点的职责。
- 拼装规则 Dev Spec 未定义，接入只会迫使我们发明规则（违反 D1 同一
  取舍），且会造成对尚不存在的下游节点的前向依赖——上游先建、下游后
  接，接口冻结后才允许消费（本仓库一贯的依赖纪律）。
- 保持零依赖的纯静态数据文件，也让 A06 的回归面最小：新增独立文件
  不触碰任何既有代码路径。

## D4 — `name` 占位值选择 "Host" 的理由

**决策**：`name` 默认值为中性的 `"Host"`。

**理由**：
- 需要一个非空字符串使类型契约成立（A07），但具体叫什么名字（某个 IP/
  角色名/主播昵称）是真实创作内容——Dev Spec 未定义，本节点不发明。
- `"Host"` 是角色名的功能化占位：不携带任何性格/背景/世界观暗示，
  与 D1 的"不发明创作内容"原则一致，也不会在将来真实名字填入时产生
  误导性的既有默认。
- 真实人设（含名字）是创作/产品决策，与 voiceDescription 一样留给
  USER 未来以某种配置方式填入；届时 `getHostPersona()` 的调用方无需
  改动（返回形状不变，仍是 `{ name, voiceDescription }`）。
