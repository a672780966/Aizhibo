# DEV-058 DECISIONS

本文件记录 DEV-058（Host Avatar）执行过程中的工程决策与依据。权威范围
依据：`specs/tasks/TASK-PACKAGE-DEV-058.md`、CR-014（`specs/dev/DAG.md`
第 339 行 / `specs/audit/SPEC-AUDIT-001.md` 第 362 行）、USER 2026-09-07
裁决。

## D1：只定义状态形状 + 静止默认值，不实现任何带具体时间参数的驱动/切换逻辑

- **决策**：本节点只产出 `HostAvatarState` 数据形状与
  `idleHostAvatarState` 静止默认值；不实现张嘴/闭嘴切换间隔、呼吸
  周期时长等任何带具体时间参数的驱动/切换函数。
- **依据**：Dev Spec 第 2707-2710 行与 CR-014 都没有定义任何具体的
  切换频率、呼吸周期时长或"多少帧算一个周期"这类实现参数——这些是
  纯粹的创作/表演节奏决策，不是工程决策。USER 已于 2026-09-07 就此
  现实核对裁决：本节点只定义状态形状，不实现带时间参数的驱动逻辑。
  与 DEV-052（Host Persona，只搭数据形状不发明人设创作内容）、
  DEV-053（Host Mood，只搭存储原语不发明推导算法）一脉相承。"多快
  切一次嘴型""呼吸周期多长"留给未来集成真实 PNG 素材与渲染管线时的
  产品/创作决策。

## D2：用两个独立的二元状态（口型 + 呼吸）而不是单一枚举

- **决策**：`HostAvatarState = { mouth: 'open'|'closed'; breathing:
  'inhale'|'exhale' }`，口型与呼吸是正交、独立的两个维度。
- **依据**：CR-014 裁定的范围是"口型微动 + 呼吸微动"两个独立现象，
  二者未来由不同信号驱动（口型跟说话/音频信号，呼吸是周期性相位），
  状态维度天然独立。合并成单一枚举（如 4 个组合态）会丢失"口型变了
  但呼吸相位没变"这类合法中间态的表达力，也会让未来驱动逻辑更难
  各自演进。

## D3：不接入 renderer/Presentation 层，不定义任何真实 PNG 资源路径

- **决策**：本节点不 import `renderer` 相关任何模块，不定义任何真实
  资源文件路径/加载逻辑。
- **依据**：本节点产出的是"Avatar 当前处于什么视觉状态"这一数据结构
  本身，不是真实的渲染/资源加载逻辑。把 `HostAvatarState` 映射成具体
  要显示哪张 PNG、怎么在画面上渲染，是未来某个尚未建造的 Presentation
  层集成节点的职责（类似 M2 `Character Renderer` DEV-022，但本节点
  不改动、不接入它）。零依赖原则同时保证本模块可在任何环境被安全
  引用。

## D4：`idleHostAvatarState` 选择"闭嘴 + 呼气"作为默认值

- **决策**：唯一静止默认值为 `{ mouth: 'closed', breathing: 'exhale' }`。
- **依据**："没有任何外部驱动信号时"的中性静止画面：嘴巴闭合（不说话
  就不张嘴）、处于呼气相位（呼吸周期中"从吸气回到平静"的落点，代表
  一个完整呼吸周期结束后的稳定静止帧）。不发明规范之外的新取值——
  两种口型状态与两种呼吸相位全部来自 Dev Spec / CR-014 的二元划分。
